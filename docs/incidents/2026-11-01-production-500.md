# 2026-11-01: every page on growthstats.io returned 500

**Impact:** from about 08:25 to 13:36 UTC (about 5 hours), every page on the live site returned `500 MIDDLEWARE_INVOCATION_FAILED`. The Studio (`/admin`) still worked. Fixed by #101.

**Detected:** by hand, hours after it started. There was no uptime check.

## Cause

The live site runs `main`, and the multilingual work lives on `develop`. Both read the same Sanity dataset, `production`.

- `main` still ran the template's original middleware, which calls `getTranslations()` on every request. That query lists every page's translations by following the references in `translation.metadata`.
- #64 backfilled `language` on the published pages, so the query now matched all of them.
- #70 and #71 created German pages as **drafts** and linked them to the English pages through `translation.metadata`, on purpose, with nothing published.
- In the published perspective a reference to a draft-only document resolves to `null`. Each page's translations came back as `[{ …en }, null]`.
- The middleware ran `t.translations?.some(({ slug }) => …)`, and destructuring `null` threw on every request.

No code changed on `main`. The writes to the production dataset broke it. Every check we had (CI, local browser checks, the `develop` deployment) ran `develop`'s code, which already treats unpublished translations as missing (ADR 0002), so none of them could catch it.

## Fix

#101, on `main`: both translation queries keep only the references that resolve (`translations[defined(value->_id)]`). `develop` doesn't have those queries, and the merge back into `develop` keeps `develop`'s version.

## What changed so it doesn't happen again

1. **Uptime check:** `.github/workflows/uptime.yml` runs `scripts/agent/smoke-prod.sh` every 15 minutes and opens a "Production is down" issue when it fails. Scheduled workflows only run on the default branch, so it starts after the next release to `main`.
2. **Agents treat the production dataset as live:** the `work-issue` skill and ADR 0004 now say that a write to `production` is read by `main`'s code too. Before writing, check that `main` handles the new data. After writing, run `scripts/agent/smoke-prod.sh`, and if it fails, undo the write and stop.
3. **Ship `develop` before more content work:** until `develop` is released, `main` keeps running the old code against new content. Don't publish German pages until then.
